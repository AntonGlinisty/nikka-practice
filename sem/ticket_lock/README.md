# Ticket Lock

Рассмотрим самую простую блокировку -- [test-and-set (TAS) spinlock][spinlock].
При попытке ее захватить, потоки-участники пытаются перевести ее состояние из
незахваченного в захваченное с помощью атомарных операций [`swap`][swap] или
[`compare_exchange`][compare-exchange].
Несложно увидеть, что при неудачном стечении обстоятельств, один поток может последовательно
не успевать захватить блокировку, из-за чего конкретный поток не может совершить
прогресс, несмотря на то, что блокировка захватывается и отпускается другими потоками.
Такая ситуация называется _голодание_ (_starvation_). Иными словами, TAS spinlock
не является _честной_ блокировкой.

[spinlock]: https://sergey-v-galtsev.gitlab.io/labs-description/lab/book/5-sync-2-spinlock.html
[swap]: https://doc.rust-lang.org/core/sync/atomic/struct.AtomicBool.html#method.swap
[compare-exchange]: https://doc.rust-lang.org/core/sync/atomic/struct.AtomicBool.html#method.compare_exchange

Для обеспечения честности, блокировки часто выстраивают ожидающие потоки в очередь
и передают владение блокировкой в соответствии порядком потоков в этой очереди.
Один из самых простых подобных примеров -- ticket lock. Принцип работы ticket lock'а
напоминает очередь по талону (ticket) в физических заведениях. Ticket lock поддерживает
два числа: номер текущего владельца блокировки (`current`) и номер следующего
доступного _талона_ (`next_ticket`).
Когда поток пытается захватить блокировку, он берет себе первый доступный талон
и ожидает, пока очередь (номер текущего владельца) не дойдет до него, после чего
блокировка считается захваченной. Освобождение же блокировки заключается в передаче
блокировки следующему потоку в очереди.

Реализуйте алгоритм ticket lock'а.

## Запуск тестов

При запуске тестов указывайте параметр `--test-threads=1`,
чтобы тесты запускались по одному и не мешали друг другу:

```bash
cargo test -- --test-threads=1
```
