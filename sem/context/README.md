# context

Состояние процессора определяется набором регистров. Набор значений
регистров называют контекстом. С точки зрения программы на Rust
контекст - это текущая выполняющаяся строчка кода + значения некоторых
локальных переменных.

В этой задачи вам нужно реализовать функции сохранения и
восстановления контекста `save()` и `load()` в файле `src/impl.s`.
В файле `src/lib.rs` есть строки, которые показывают их интерфейс в Rust.
Возможность сохранить
и восстановить контекст необходима для реализации многозадачности,
правда там требуется немного другая семантика. Мы же будем копировать
семантику функций `setjmp()/longjmp()`, прочитать про которые можно в `man`:

```
$ man 3 setjmp
$ man 3 longjmp
```

Функция `save()` сохраняет текущий контекст и возвращает 0. После
этого, пользователь может вызвать `load()` и исполнение программы
продолжится так, будто функция `save()` вернула 1.

`save()` может "возвращаться несколько раз", это чем-то похоже на
системный вызов `fork()`.

Подобную семантику невозможно выразить в терминах языка Rust, поэтому
функции `save()` и `jump()` можно реализовать только на
ассемблере. К тому же, компилятор должен знать про особое поведение
этих функций и отключать некоторые оптимизации в точках их
использования.

Сохранённый контекст описывается структурой `Context`:

```
struct Context {
    rip: usize,
    rsp: usize,
    rbp: usize,
}
```

 - Значение регистра `rip` - самая важная часть состояния. Её должен
   начать выполнять процессор после вызова `load()`. Требование
   "исполнение программы продолжится так, будто функция `save()`
   вернула 1" можно легко выполнить, сохранив в `rip` адрес возврата
   из функции `save()`.
 - `rsp` - указатель на вершину стека. Вам нужно вычислить значение
   `rsp` соответствующее значению `rip` которое вы сохранили.
 - `rbp` - указатель на начало фрейма. Вам достаточно будет просто
   сохранить это значение.
